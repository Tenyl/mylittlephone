# Vercel 托管 API 与私有默认角色卡设计

## 目标与边界

把“小手机”的默认聊天能力从浏览器直连模型改为同源 Vercel Function 代理。默认 API 地址、API Key、模型名称和迷迭香完整角色卡只从 Vercel 服务端环境变量读取，不进入前端源码、静态资源、请求体或浏览器存储。默认预设继续保留在前端，玩家可编辑、导入和切换；用户导入的角色卡和自定义 API 模式继续可用。

本次不实现邀请码、账号、数据库或管理后台。网址仍可直接访问；“内部分享网址”不是身份认证，因此服务端同时限制请求尺寸、历史长度与最大输出，部署者还应在模型供应商侧设置预算上限。

## 两种 API 模式

### 站点托管模式（默认）

浏览器向同源 `/api/chat` 发送本轮输入、可见聊天历史、当前前端预设、启用的世界书、变量和当前角色标识。请求不包含默认 API 地址、Key、模型或默认角色卡提示词。

服务端按角色标识决定角色卡来源：

- 当前角色是内置迷迭香：忽略浏览器提供的角色内容，使用 `MANAGED_CHARACTER_CARD_B64` 中的私有角色卡。
- 当前角色是玩家导入角色：接收并校验浏览器传来的角色卡，使玩家仍能使用托管 API 与自定义角色聊天。

服务端使用现有提示词组装器合并角色卡、前端预设、世界书、历史和输入，再使用环境变量中的模型配置调用 OpenAI 兼容接口。上游 SSE 只以流的形式转发；上游错误正文、认证头和供应商细节不返回浏览器。

### 用户自定义 API 模式

保留现有浏览器直连逻辑。玩家主动选择“自定义 API”后，地址、Key、模型与可选辅助 API 仍只保存在自己的 IndexedDB 中。该模式下提示词继续在浏览器组装，因此仅适合玩家自己的角色卡与配置，不承诺隐藏内容。

切换模式不会清空自定义 API 值。升级已有数据时：如果旧设置中存在完整的地址、Key 和模型，则迁移为自定义模式；否则迁移为托管模式。

## 请求与数据流

```text
浏览器（预设可编辑）
  ├─ 托管模式 ──> /api/chat
  │                 ├─ 读取 Vercel API 地址 / Key / 模型
  │                 ├─ 内置角色：读取私有迷迭香角色卡
  │                 ├─ 合并前端预设、世界书、历史和输入
  │                 └─ 调用上游并仅转发 SSE
  └─ 自定义模式 ──> 玩家配置的 OpenAI 兼容 API（原有逻辑）
```

托管请求的前端预设发送完整 `settings` 和 prompt order，服务端再调用 `buildPresetGenerationOptions`，确保 temperature、max tokens、top-p、penalties、stop 等已支持参数完整进入上游请求。服务端模型字段始终覆盖任何浏览器输入。

## 服务端环境变量

- `MANAGED_LLM_BASE_URL`：OpenAI 兼容 API 根地址。
- `MANAGED_LLM_API_KEY`：API 密钥。
- `MANAGED_LLM_MODEL`：默认模型。
- `MANAGED_CHARACTER_CARD_B64`：内部 `CharacterCard` JSON 的 Base64 编码。
- `MANAGED_MAX_OUTPUT_TOKENS`：可选的服务端最大输出上限；未设置时允许前端预设完整传入，协议安全上限为 65535。

这些变量只能在 Vercel 项目环境变量中配置，不能使用 `VITE_` 前缀。仓库只提交变量名示例和编码工具，不提交真实值。

## 默认角色卡静态资源

前端仍需保留一个公开的“角色外壳”，用于头像、名称、首条消息和 UI 展示。但 PNG 的 `chara` 与 `ccv3` 数据块必须同步清空 description、personality、scenario、system prompt、post-history、示例对话和作者注释等敏感字段。

内置内容版本升级后，已有浏览器会用脱敏外壳刷新本地内置角色记录，从 IndexedDB 中删除历史版本曾保存的提示词。此操作不能抹除已公开 Git 历史，部署者应把原提示词视为已经公开，并仅把后续私有版本放入 Vercel 环境变量。

## 错误、安全与性能

- 仅接受 `POST application/json`，拒绝超大正文、过长单条消息、过多历史和畸形对象。
- 默认角色标识固定，浏览器无法用同一 ID 覆盖服务端角色提示词。
- 最大输出由服务端上限二次约束，不能只信任前端预设。
- API 响应使用 `Cache-Control: no-store`；Cloudflare 对 `/api/*` 必须绕过缓存。
- 上游错误统一为中文通用错误，不回传响应正文或内部 URL。
- 使用 `request.signal` 传播取消，避免玩家停止生成后继续消耗模型额度。
- 不在日志中输出请求提示词、环境变量或上游响应正文。

## 设置界面

“API 与设置”主 API 页顶部提供“站点托管 / 自定义 API”分段控件：

- 托管模式只显示服务由站点维护的说明，不展示地址、Key 或模型字段；辅助 API 设置禁用并说明原因。
- 自定义模式恢复原有地址、Key、模型、模型列表和连接测试控件；辅助 API 继续可选。

准备度在托管模式下不再要求本地 API 字段，默认角色与默认预设就绪后可直接聊天；自定义模式沿用原有完整性检查。

## 验收标准

1. 全新浏览器无需导入角色卡、预设或配置本地 API 即可发起托管请求。
2. 托管请求体与静态产物中不存在默认 API 地址、Key、模型和迷迭香敏感提示词。
3. Vercel Function 使用服务端模型和私有角色卡组装请求，并完整应用前端预设生成参数。
4. 玩家编辑默认预设后，下一次托管请求使用新预设；预设仍可导入与切换。
5. 玩家导入角色卡后可在托管模式使用；切换自定义 API 后原有直连能力正常。
6. 内置 PNG 的 `chara` 与 `ccv3` 数据同步且敏感字段为空，升级会清理 IndexedDB 中的旧提示词。
7. 服务端不泄露上游错误、认证信息或配置，且具备基本请求和输出上限。
8. 单元测试、类型检查、生产构建和浏览器关键流程通过，修改提交并推送到 GitHub。
