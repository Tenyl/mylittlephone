# 澄语全窗口 QQ 沉浸聊天设计

## 目标

将当前桌面三栏角色聊天界面改为全窗口 QQ 式沉浸聊天。玩家完成角色卡、预设与 API 配置并进入会话后，屏幕只保留联系人信息、双方消息、输入状态和消息输入框；所有配置集中到右上角齿轮管理中心。

## 两种产品状态

### 准备状态

没有可用会话时显示全窗口准备向导。向导继续负责导入角色卡、导入预设、配置 API 和可选世界书。右上角始终提供设置齿轮，玩家可直接打开管理中心。

### 沉浸聊天状态

存在当前会话与角色时自动进入沉浸聊天，不提供需要手动开启的“专注模式”。刷新页面后仍直接恢复当前会话与滚动位置附近的聊天内容。

聊天状态不显示：

- 左侧功能导航栏；
- 右侧上下文、世界书、Token、变量和 IndexedDB 状态栏；
- “本地浏览器存储”“调用角色卡与 N 本世界书”等技术文案；
- 剧情选项卡片；
- 思考折叠区、思维链或中间生成正文；
- 常驻的编辑、删除、分支按钮。

## 全窗口结构

聊天页面使用三段式结构：

1. 顶栏：角色头像、角色昵称、在线/正在输入状态、会话历史按钮和设置齿轮。
2. 消息时间线：只显示玩家消息与角色最终回复；内容列在宽屏上限制可读宽度，页面背景铺满窗口。
3. 输入栏：只显示文本输入与发送/停止按钮。高级操作不在输入栏持续出现。

顶栏齿轮的点击区域不小于 44×44px。配置不完整或连接失效时，齿轮显示不依赖颜色的小型状态点与可访问名称；正常状态不显示徽标。

## 齿轮管理中心

点击齿轮打开覆盖式管理中心，聊天保持在背景中且不发生布局位移。桌面端从右侧滑入 420–480px 抽屉，手机端使用接近全屏的底部/右侧面板。

管理中心首页包含当前配置摘要和以下入口：

- 角色卡；
- 世界书；
- 对话预设；
- 主次 API 与游戏设置；
- 会话变量；
- 本地数据、备份和清除。

会话历史保留为顶栏独立入口，因为它属于聊天行为而非系统配置。关闭管理中心必须恢复齿轮焦点、原消息滚动位置和未发送输入草稿。复杂世界书与预设编辑器继续作为二级模态框显示在管理中心之上。

## 最终消息呈现

网络层继续采用流式接收，以便及时停止和处理标签；可见层采用整条呈现：

1. 玩家发送后立即写入并显示玩家气泡。
2. 创建一个不可见正文的流式助手消息，同时在消息末尾显示角色头像与三点输入气泡，顶栏状态改为“正在输入…” 。
3. `<thinking>`、`<think>`、中间 `<maintext>` 和普通流式增量只在内存中解析，不显示给玩家。
4. 流结束后清理控制标签，将最终 `maintext` 或安全回退文本一次性替换输入气泡。
5. 同一渲染周期移除“正在输入”状态并显示完整角色气泡。

输入提示延迟 300ms 出现，避免极快回复闪烁；超过 12 秒可以把无障碍文本更新为“仍在输入…”。视觉动画周期约 1.1 秒，并遵守 `prefers-reduced-motion`。

## 隐藏思维链和选项

- `thinking` 与 `think` 永远不渲染、不进入可导出的消息正文，也不写入最终消息的 `parsed.thinking`。
- `<option>` 仍可被解析器识别以兼容既有输出，但最终消息保存时清空 `parsed.options`，界面永远不创建选项按钮。
- `<sum>` 与 `<vars>` 继续在后台用于摘要元数据和变量更新，不显示在消息时间线。
- 最终 `content` 只保存清理后的角色正文，`metadata.rawContent` 不再保留思维链原文。
- 备份和聊天导出中不得出现思维链原文。

## 停止与失败

- 玩家停止生成时，中止请求并删除尚未完成的助手占位消息，不保留半成品正文或“回复已中断”气泡。
- 失败时同样移除输入占位，通过顶部站内通知提供“回复失败，可重试”。玩家消息保留。
- 输入栏在清理完成后恢复可用；停止按钮在生成期间替代发送按钮。

## 消息操作

消息默认没有可见操作按钮。桌面悬停/键盘聚焦后出现单一“更多”按钮，手机点击该按钮打开底部操作菜单：

- 玩家消息：复制、编辑并重新发送、从这里删除；
- 角色消息：复制、重新回复、创建分支、从这里删除。

第一版不依赖长按作为唯一入口，确保键盘与触屏均可访问。

## 响应式与视觉

- 默认以 375px 手机布局为基础，增强到 768、1024 和 1440px。
- 桌面聊天窗口宽高均为视口，不保留外层悬浮卡片边距和 28px 圆角。
- 消息内容列最大宽度约 920px，双方气泡最大宽度 72%，手机端最大宽度 82%。
- 使用现有冷灰、白色、消息蓝和在线绿令牌，Phosphor 图标保持统一权重。
- 管理中心使用 180–240ms 的 opacity/transform 动效；输入点动画不改变布局尺寸。
- 所有交互目标不小于 44×44px，焦点环清晰，Escape 可关闭非破坏性弹层。

## 性能

- 保留 100 条消息窗口化策略和稳定消息 ID。
- 流式 chunk 只更新内存中的隐藏消息，不触发可见正文逐字排版。
- 管理中心的复杂内容按需挂载；关闭时从 DOM 移除。
- 不新增动画依赖，只使用 CSS transform/opacity。

## 验收标准

1. 当前会话存在时，DOM 中不存在常驻左侧导航和右侧上下文栏。
2. 顶栏设置齿轮可打开包含角色卡、世界书、预设、API/设置、变量与本地数据的统一管理中心。
3. 无当前会话时仍能从准备向导和齿轮完成全部配置。
4. 生成期间只显示“正在输入”状态，不显示流式正文、思考文本或剧情选项。
5. 完成后一次性显示清理后的最终角色回复，`thinking`、`option` 与控制标签不可见。
6. 停止或失败后不保留半成品助手气泡，玩家消息保留。
7. 聊天区不显示存储、Token、世界书数量、变量或 API 等技术状态。
8. 桌面与 375px 手机无横向滚动；管理中心关闭后焦点回到齿轮。
9. 现有导入、预设、世界书、变量、会话历史和备份能力保持可用。
10. 单元测试、类型检查、生产构建和真实浏览器桌面/手机验收通过。
