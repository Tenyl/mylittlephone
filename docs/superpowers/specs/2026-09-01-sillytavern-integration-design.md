# My Little Phone 酒馆化集成设计

## 目标

将现有 React 手机 QQ 风格聊天原型改造为完全前端运行的 SillyTavern 兼容角色聊天应用。应用不再携带任何演示角色卡、世界书、预设或聊天记录；玩家首次打开时从空白状态导入自己的资料并开始对话。

## 已确认范围

- 严格以 `sillytavern-web` React 模板提供的数据模型、IndexedDB、世界书扫描、提示词组装、流式标签解析、多 API 路由、变量、回滚与分支能力为基础。
- 游戏模式启用。
- 使用默认六标签：`maintext`、`option`、`sum`、`vars`、`thinking`、`think`。
- 启用双 API 模式；主 API 负责角色回复，次 API 负责变量和总结任务。
- schema-first 状态系统关闭，因为当前技能版本明确将其保留为未来扩展项。
- 角色卡同时支持 SillyTavern PNG 与 Character Card V2 JSON。
- 只实现浏览器端，不增加服务器、代理服务、数据库服务或云端密钥存储。

## 推荐架构

### 单一状态源

用 Dexie/IndexedDB 替换当前 `useReducer + localStorage` 演示状态。复制并适配技能模板到以下边界：

- `src/sillytavern/`：领域类型、Dexie 数据库、导入器、世界书引擎、提示词组装、流式解析、变量合并、API 路由与消息编辑工具。
- `src/hooks/useSillytavern.ts`：唯一应用编排入口，负责加载持久化数据、会话操作、生成请求、停止请求、分支、回滚和通知。
- `src/features/` 与 `src/components/`：继续使用现有手机 QQ 外壳与站内反馈组件，将其数据接口切换到新的酒馆状态。

旧的 `src/domain/demoData.ts`、`src/services/mockLlm.ts`、`src/services/storage.ts` 以及与演示 reducer 绑定的状态流在新架构可用后删除。不能保留两套并行状态源。

### 数据模型扩展

技能模板原生包含世界书、预设、会话、消息、变量和设置，但没有完整角色卡表。新增 `CharacterCard` 数据表及字段归一化：

- 基础：`id`、`name`、`avatar`、`sourceFile`、`importedAt`、`spec`。
- Character Card V2：`description`、`personality`、`scenario`、`firstMes`、`mesExample`、`creatorNotes`、`systemPrompt`、`postHistoryInstructions`、`alternateGreetings`、`tags`、`creator`、`characterVersion`、`extensions`。
- 激活关系：设置只保存 `activeCharacterId`、`activeLorebookId`、`activePresetId` 和 `activeChatId`，记录缺失时回到明确的空状态。

数据库升级不得填充默认角色、世界书、预设或聊天。仅创建一条中性设置记录，API URL、API Key、模型和激活内容均为空；UI 模式默认为游戏模式、API 模式默认为双 API。

### 角色卡导入

JSON 导入器接受 Character Card V2 的 `spec: "chara_card_v2"` 包装结构，也兼容常见的顶层 `data` 结构。PNG 导入器在浏览器中读取 PNG 文本块，提取 SillyTavern 使用的 `chara` 元数据并 Base64 解码为 UTF-8 JSON；PNG 自身转换为本地头像 Data URL。

导入过程必须校验文件类型、文件大小、元数据存在性和必填角色名，错误显示在站内通知/表单附近。导入成功后写入角色表并将其设为当前角色，不自动创建聊天；玩家仍需选择预设并完成 API 设置。

### 提示词与生成数据流

一次消息发送的数据流为：

1. UI 检查当前角色、当前预设和主 API 完整性。
2. 世界书引擎根据最近消息和角色输入扫描激活条目。
3. 提示词组装器按预设顺序合并角色卡字段、世界书内容、会话历史、变量、用户名和格式提示词。
4. API Router 将剧情请求发送到主 API；变量/总结任务优先发送到次 API。
5. Stream Parser 增量提取六类标签；正文与选项实时显示，思考内容按设置折叠或隐藏。
6. 回复完成后应用 `<var .../>` 更新、保存总结与消息元数据，再持久化会话。

API Key 只写入当前浏览器 IndexedDB，并在设置页明确说明请求会直接发送到用户填写的端点。应用不记录、不打印、不导出明文密钥；完整备份默认剔除 API Key。

## 界面与交互

### 空白启动页

无角色或预设时，聊天区域显示三步准备向导而非虚构联系人：

1. 导入角色卡（必需，PNG/V2 JSON）。
2. 导入预设并配置主 API（必需）。
3. 导入世界书、配置次 API（世界书可选；双 API 配置缺失时明确降级或阻止对应任务）。

每一步显示完成状态、直接操作按钮和缺失原因。只有角色、预设与主 API 均可用时才允许开始新会话或发送消息。

### 主聊天界面

- 延续现有手机 QQ 风格的会话列表、聊天头部、气泡和上下文栏。
- 游戏模式在助手气泡中分别渲染正文、选项和思考折叠区；自由输入始终可用。
- 支持流式光标、停止生成、重新生成、编辑用户消息、从指定消息删除后续内容、从任意消息建立分支。
- 当前角色、世界书、预设与 API 就绪状态在桌面上下文栏和移动端信息面板中一致展示。
- 长会话达到 100 条以上时使用虚拟化或等效的窗口化策略，避免一次渲染全部消息。

### 管理界面

- 角色卡库：导入、列表、预览、选择、导出和删除。
- 世界书：导入、新建、条目搜索、编辑、启停、排序与删除。
- 预设：导入、编辑生成参数、编辑提示词顺序、选择和删除。
- 历史会话：新建、切换、重命名、删除和显示父分支来源。
- 变量：查看自动变量、手动编辑并显示最后更新时间。
- 设置：主 API、次 API、模型拉取、连通测试、六标签、格式提示词、思考显示、备份与清除数据。

所有破坏性操作使用现有站内确认模态框；错误和成功反馈使用带 `aria-live` 的 Toast。不得使用 `alert`、`confirm`、`prompt` 或 Emoji。

## 视觉规范

- 保留当前高端、轻盈的手机 QQ 视觉语言，以消息蓝 `#2563EB`、在线绿 `#059669`、白色与冷灰为语义令牌基础；不采用检索结果中与本产品不相符的营销落地页结构。
- 统一使用 `@phosphor-icons/react`，相同层级保持一致的线条权重。
- 点击目标不小于 44×44 CSS 像素，表单输入在移动端不小于 16px 字号。
- 动效仅使用 `transform` 与 `opacity`；列表与面板采用 150–300ms 的状态过渡，并支持 `prefers-reduced-motion`。
- 模态框打开后陷阱焦点，关闭后恢复到触发按钮；Escape 可关闭非破坏性弹层。
- 在 375、768、1024、1440 像素宽度以及移动横屏下无横向滚动和内容遮挡。

## 清理与迁移

- 删除源码中的内置角色卡、世界书、预设和聊天数据。
- 删除 Mock LLM 与旧 reducer/localStorage 持久化路径。
- 数据库首次升级时移除已知旧键 `luma-character-chat:v1`，仅执行一次；不能清除新 IndexedDB 中由玩家导入的数据。
- 测试夹具可以保留最小的内存对象，但不能进入生产初始化路径或打包为默认可玩内容。

## 错误处理

- 导入失败：指出文件、失败原因与支持格式，不改变当前激活内容。
- API 配置不完整：禁用发送并提供打开设置的操作。
- API/CORS/超时错误：保留用户消息，标记本轮失败并提供重试。
- 流式输出中止：保留已接收正文并标记为已中断。
- IndexedDB 失败：显示持久化不可用警告，不伪装为保存成功。
- 删除/覆盖/全量导入：显示对象数量和影响范围，必须二次确认高风险清除。

## 验收标准

1. 全新浏览器数据下没有角色、世界书、预设和会话，出现中文准备向导。
2. PNG 与 Character Card V2 JSON 均可导入并正确显示字段及头像。
3. SillyTavern 世界书与预设 JSON 可导入、编辑、选择并在刷新后保留。
4. 主/次 API 可分别配置、拉取模型与测试连接，生成请求按任务路由。
5. 六标签流式输出正确拆分，正文、选项、思考、变量和总结不会混入普通气泡。
6. 会话可创建、加载、重命名、删除；刷新后消息与选择保持。
7. 用户消息可编辑和重新生成，可从指定点删除后续消息，可从任意消息分支。
8. 变量可手动编辑，`<var .../>` 更新可自动合并并持久化。
9. 项目中不存在生产演示数据、Mock LLM、Emoji 图标和浏览器原生警告框。
10. 单元测试、类型检查和生产构建通过，并完成真实浏览器的桌面与 375px 移动端验收。
