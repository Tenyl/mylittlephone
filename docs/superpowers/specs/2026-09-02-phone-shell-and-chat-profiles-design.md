# 澄语手机外壳与聊天资料定制设计

## 目标

在不拆分桌面端和移动端聊天逻辑的前提下，让桌面端呈现为一台可操作的实体手机，让移动端保持原生全屏聊天体验；同时精简默认角色管理，并增加玩家全局资料和当前会话角色备注资料。

## 产品边界

- 继续使用现有 React、Dexie、Vite 和 Phosphor Icons，不增加后端接口或云端用户系统。
- 默认迷迭香的完整角色提示词仍只由服务端管理。
- 玩家资料保存在当前浏览器；角色备注名和替换头像只属于当前会话。
- 角色备注名只改变聊天界面显示，不替换角色卡名称，也不进入角色提示词或 API 请求。
- 本轮不增加账号同步、社交联系人、语音、图片消息或 API 限流。

## 采用方案

使用一套 `AppShell`、`ChatHeader`、`MessageList` 和 `Composer` 组件，通过响应式 CSS 切换外壳：

- 桌面端由 `phone-device` 承载手机边框、顶部听筒/镜头、侧键和内屏裁切。
- 移动端隐藏所有装饰外壳，让同一个内屏固定铺满动态视口。
- 不使用整体 `transform: scale()`，避免字体模糊、点击坐标偏移和无障碍尺寸失真。
- 不复制两套聊天组件，避免桌面与移动功能逐渐分叉。

## 响应式手机聊天

### 桌面端

桌面断点使用居中的手机设备：内容宽度取 `min(430px, 视口宽度 - 64px)`，内容高度取 `min(880px, 视口动态高度 - 48px)`。手机壳采用深色多层边框、内侧高光、柔和投影、顶部听筒/镜头和非交互侧键。屏幕保持现有浅蓝 QQ 聊天气质，外部背景继续使用克制的冷灰蓝渐变。

手机壳只负责视觉和裁切；所有真实按钮仍位于语义化聊天界面中。管理中心继续作为页面级模态框覆盖在手机上方，不被狭窄内屏限制。

### 移动端

在不超过 760px 的视口中去除边框、圆角、听筒、镜头、侧键和外部留白。根节点、应用舞台、手机屏幕和聊天列共同锁定到 `100dvh`，并以 `100svh` 作为稳定下限。

聊天列固定为三行：顶部导航、`minmax(0, 1fr)` 消息区、底部输入区。只有消息区滚动，页面本身不滚动。顶部和底部同时使用 `env(safe-area-inset-*)`，消息区预留输入区空间，确保空会话、短会话、长会话以及软键盘出现时输入区都保持在可见底部。

手机横屏时保留同一骨架并压缩顶部高度和垂直间距，不隐藏核心按钮。交互目标至少 44×44px，输入字体至少 16px，避免 iOS 自动缩放。

## 资料模型

### 玩家全局资料

`AppSettings` 新增 `userAvatar: string`，继续使用现有 `userName` 作为玩家昵称。设置中的“我的资料”允许：

- 编辑玩家昵称；
- 从本机选择 PNG、JPEG 或 WebP 头像；
- 预览并移除自定义头像；
- 使用头像缺省图形作为回退。

昵称继续进入 `{{user}}` 宏；头像只用于界面。资料修改立即保存到 IndexedDB，并作用于所有会话的玩家气泡。

### 当前会话角色资料

`ChatSession` 新增两个可选字段：

- `characterDisplayName?: string`：当前会话的角色备注名；
- `characterAvatar?: string`：当前会话替换头像的数据 URL。

聊天头部、角色消息头像、角色消息元信息和输入框提示优先使用会话覆盖值，未设置时回退到角色卡。清除覆盖后立即恢复角色卡显示。分支会话继承覆盖值，新建会话不自动复制其他会话的覆盖。

这些字段不修改 `CharacterCard`，不改变角色卡库中的信息，不替换发送到 LLM 的 `characterName`。

### 持久化与兼容

Dexie 数据库版本提升，旧设置缺少 `userAvatar` 时回填空字符串，旧会话缺少覆盖字段时自然回退。完整备份包含玩家头像与会话覆盖，仍清空主次 API Key。导入旧备份保持兼容。

头像导入限制文件类型和大小，并在读取前给出站内错误；头像数据只写入 IndexedDB，不上传到托管聊天接口。

## 设置与管理中心

### 角色卡库

内置迷迭香选中时仅显示头像、名称、当前启用状态和启用按钮：

- 不显示“内置角色设定已隐藏”；
- 不显示来源文件；
- 不显示导入时间；
- 不显示删除按钮；
- 不显示角色提示详情。

用户导入角色继续显示描述、性格、场景、初始消息、来源文件、导入时间、启用和删除操作。控制器层同时拒绝删除内置角色，避免只依赖 UI 隐藏。

### API 与设置

现有“游戏显示”中的能力经审计均有效，因此改名并拆分：

- “我的资料”：玩家昵称与头像；
- “回复格式”：解析标签、格式提示词与恢复默认值；
- “聊天服务”：托管或自定义 API；
- “次 API”：只在自定义模式下提供；
- “本地数据”：备份、导入和重置。

不保留含义模糊的“游戏显示”标签。

### 会话变量

会话变量会被模型输出更新、写入当前会话，并进入下一轮提示词，因此保留。入口和说明标记为高级能力；无活动会话时给出明确空状态，编辑器继续执行 JSON 校验和站内错误提示。

### 当前聊天资料入口

在管理中心增加“当前聊天”入口。该页集中编辑当前会话的角色备注名与头像，并明确说明只改变本会话显示。没有活动会话时显示不可编辑的说明状态。

## 消息显示

- 玩家消息非连续组的首条显示玩家头像，元信息显示玩家自定义昵称。
- 角色消息使用当前会话备注名与头像。
- 连续同侧消息继续折叠重复头像，保持 QQ 式紧凑节奏。
- 顶栏和输入框提示同步使用角色备注名。
- 头像均声明固定尺寸和 `object-fit: cover`，避免加载时布局位移。

## 动效、无障碍与性能

- 手机进入只使用轻微 opacity/translate，不动画宽高；遵守 `prefers-reduced-motion`。
- 装饰性听筒、镜头和侧键不进入无障碍树，不接收指针事件。
- 所有头像文件输入都有可见标签、格式说明和错误反馈。
- 图标按钮保留明确的 `aria-label`、焦点环和 44px 点击区域。
- 聊天最多渲染最近 100 条消息的现有策略保持不变。
- 头像在浏览器端限制体积；不新增外部字体、图片或动画依赖。

## 验收标准

1. 页面标题和相关产品标题统一为“澄语”。
2. 宽屏中聊天界面位于完整手机外壳内，聊天仍可正常滚动、输入、发送和打开管理中心。
3. 375px、390px 和移动端横屏中无手机壳、无横向滚动；空会话与短会话输入区位于页面底部。
4. 移动端顶部、输入区和管理中心尊重安全区，软键盘打开后输入区保持可见。
5. 默认迷迭香没有隐藏提示说明、来源、导入时间或删除操作，只能查看启用状态或启用。
6. 用户导入角色仍保留详情、来源、导入时间和删除能力；内置角色无法从控制器删除。
7. “游戏显示”不再出现；有效功能分别位于“我的资料”和“回复格式”。
8. 会话变量保留且其修改会进入下一轮提示词，无会话时显示明确状态。
9. 玩家昵称和头像在聊天界面显示，刷新后保持；备份导出与导入后可恢复。
10. 当前会话可以独立设置和清除角色备注名、头像；其他会话和底层角色卡不受影响。
11. 会话备注名不会替换 API 请求或角色卡中的真实角色名。
12. 自动化测试、类型检查、生产构建、桌面与移动真实浏览器视觉验收全部通过。
